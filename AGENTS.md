# Architecture decisions

- Framework migration (source was a Vite SPA with react-router-dom): app logic lives in TanStack Start — the whole app is one client-only route (`src/routes/index.tsx`, `ssr: false`) that renders the animated login page when signed out and `src/components/FoodLensIndex.tsx` when signed in; never reintroduce react-router-dom, `src/App.tsx`, or `src/pages/`.
- Auth is Clerk / Cloud (email/password + Google); session shape comes from `src/hooks/useClerkAuth.ts` which mirrors the source app's `AppUser` interface.
- AI calls are server-side only: `src/services/geminiService.ts` wraps `createServerFn`s (middleware `requireSupabaseAuth`) calling the AI Gateway with `google/gemini-3.8-flash`; never call Gemini or any AI key from browser code, and never put AI keys in `VITE_*` vars.
- Analysis `max_tokens` is 2000 (800 truncated the required JSON); chat-mode calls budget their own tokens (autocomplete needs ~1200 because reasoning tokens share the cap). `chatWithAI` modes (`autocomplete`, `product-info`, `food-history`, `comparison`, `diet`) each return their own raw JSON matching the display component's interface; only the image-analysis path (`analyzeProduct`) runs through `normalizeAnalysisResult` — never wrap other modes in it.
- User history stays in localStorage (`useHistoryStore`, key `foodie-analysis-history`, max 50) — the source app has no server-side data model; add a database table only if the user asks for cross-device history.
- Design system: HSL triplet CSS variables in `src/styles.css` switched by a `data-theme` attribute on `<html>` (FoodLens default + 14 themes); Tailwind v4 maps them via `@theme inline` with `hsl(var(--x))`. Custom shadcn-style UI components were copied from the source and adapted for strict TS.
